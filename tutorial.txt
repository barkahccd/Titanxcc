TitanxBot — Titan Exchange testnet (testnet.titanx.cc), multi-akun, full API
============================================================================

Bot bisa jalan 1 akun (seperti dulu) ATAU banyak akun paralel, tiap akun lewat proxy sendiri.
Pilih salah satu di bawah.

============================================================================
A. SATU AKUN (cara lama, tetap jalan)
============================================================================

Langkah 0 — install (sekali)
  cd TitanxBot-Sipal
  npm install

Langkah 1 — isi account.json
  {
    "loginMode": "google",          <- akun yang sudah kamu buat pakai Google
    "twoCaptchaKey": "ISI_KEY_2CAPTCHA",  <- dipakai SEKALI waktu bind party (Turnstile)
    "referralCode": "",             <- kode invite. Wajib kalau akun belum pernah "Enable trading"
    "evmPrivateKey": "",            <- cuma untuk loginMode "evm"
    "proxy": ""                     <- opsional, http://user:pass@host:port
  }

Langkah 2 — login Google (sekali)
  node index.js login
  -> Chrome kebuka (profil khusus bot, bukan Chrome harian kamu).
  -> Klik "Continue with Google", pilih akun Google yang SAMA dengan yang kamu pakai di web.
  -> Setelah dilempar ke testnet.titanx.cc, Chrome tutup sendiri. Terminal print status akun.
  Kalau Google menolak ("browser not secure"):
  node index.js login --manual

Langkah 3 — tes dulu tanpa order
  set "dryRun": true di config.json ; node index.js once

Langkah 4 — jalan beneran
  set "dryRun": false ; node index.js        (atau: pm2 start index.js --name titanxbot)

============================================================================
B. BANYAK AKUN PARALEL (wajib proxy.txt)
============================================================================

Ide: tiap akun jalan di proses sendiri, lewat proxy sendiri, state-nya kepisah total
(session + profil Chrome + log). Satu proses induk menampilkan 1 dashboard ringkas untuk semua.

Langkah 0 — install (sekali): cd TitanxBot-Sipal ; npm install

Langkah 1 — account.json = NILAI DEFAULT bersama
  Field di account.json (twoCaptchaKey, referralCode, loginMode) dipakai semua akun sebagai default.
  Tiap akun boleh menimpa lewat accounts.json.

Langkah 2 — buat accounts.json (contoh ada di accounts.example.json)
  [
    { "label": "A1" },
    { "label": "A2", "referralCode": "KODE-LAIN" },
    { "label": "A3" }
  ]
  - Jumlah akun = jumlah elemen array.
  - label = nama bebas (huruf/angka/._-), dipakai untuk folder state + judul di dashboard.
  - Field yang boleh ditimpa per akun: label, loginMode, twoCaptchaKey, referralCode,
    evmPrivateKey, proxy. Yang tidak diisi ikut account.json.

Langkah 3 — buat proxy.txt (WAJIB, contoh di proxy.example.txt)
  Satu proxy per baris: http://user:pass@host:port
  Akun ke-1 pakai baris ke-1, akun ke-2 baris ke-2, dst. Baris proxy harus >= jumlah akun,
  kalau kurang bot menolak jalan. Baris kosong & '#' diabaikan.
  (Login Google lewat Chrome tetap pakai koneksi langsung; SEMUA trafik API bot lewat proxy akun itu.)

  Auto-rotate proxy: kalau proxy akun error terus (gagal connect / diblok Cloudflare 403), bot otomatis
  pindah ke proxy lain dari proxy.txt, simpan ke session.json akun itu, dan terus dicoba (rotate + retry)
  sampai dapat yang jalan — tidak pernah nyerah. Atur di config.json: proxyRotate (on/off),
  proxyRotateAfter (gagal berapa kali sebelum ganti). Proxy hasil rotate ikut ke-save, jadi kalau
  folder accounts/ di-copy ke VPS, proxynya kebawa.

Langkah 4 — login SEMUA akun (satu per satu, tidak paralel)
  node index.js login
  -> Chrome kebuka untuk akun A1 (profil akun A1). Login Google A1. Chrome tutup.
  -> lalu akun A2, lalu A3 ... satu jendela pada satu waktu.
  Login ulang satu akun saja:  node index.js login --account A2
  Mode manual:                 node index.js login --manual
  (akun loginMode "evm" dilewati — tidak perlu login.)

Langkah 5 — tes tanpa order
  set "dryRun": true ; node index.js once      (semua akun jalan 1 siklus lalu berhenti)

Langkah 6 — jalan beneran
  set "dryRun": false
  node index.js                 (semua akun paralel + dashboard fleet)
  node index.js --account A2     (jalankan 1 akun saja di depan, dengan dashboard detail lama)
  node index.js status           (snapshot ringkas semua akun, read-only, aman walau bot jalan)

Dashboard fleet (banyak akun):
  Satu baris per akun: AKUN | NILAI | uPnL | POS | SESI | FAUCET | STATUS.
  Baris ringkasan di atas: berapa akun jalan, total nilai, total uPnL, total volume & fee hari ini.
  Di bawah: log aktivitas gabungan semua akun (ditandai label akun).
  Akun yang mati tampil merah + kapan di-restart. Terminal sempit -> kolom SESI/FAUCET otomatis disembunyikan.
  Lewat pm2/nohup (bukan terminal) otomatis jadi log baris biasa.

State tiap akun (otomatis, jangan dibagikan):
  accounts/<label>/session.json      session API + token + cookie akun itu
  accounts/<label>/chrome-profile/   profil Chrome login akun itu
  logs/<label>.log                   log akun itu
  logs/titanxbot.log                 log proses induk (fleet)

Cocokkan session <-> akun (otomatis / smart):
  Tiap session.json dicap label akunnya saat login. Bot pakai accounts/<label>/session.json
  HANYA kalau cap labelnya = <label>.
  - Cap BEDA (file ketuker / folder di-rename / salah taruh) -> bot TOLAK akun itu dan minta
    login ulang (biar tidak kejadian trading di akun yang salah). Akun lain tetap jalan.
  - Belum ada cap / belum ada session -> dianggap belum punya akun -> perlu login.
  Cek cepat tanpa jalan: node index.js status (tiap akun kelihatan OK / MISMATCH / belum login).

Berhenti:
  Ctrl+C SEKALI = semua akun tutup posisi bot dulu, lalu berhenti rapi (tunggu beberapa detik).
  Ctrl+C DUA kali = paksa keluar; sisa posisi/order bot dibereskan otomatis saat bot jalan lagi.
  Satu akun yang perlu login lagi tidak menjatuhkan yang lain — dashboard kasih tahu akun mana.

============================================================================
C. JALAN DI VPS (headless, pm2)
============================================================================

Masalah: login Google butuh jendela Chrome buat diklik. VPS biasanya headless (tanpa GUI).
Solusi: LOGIN DI LAPTOP, lalu COPY state ke VPS. (Cara ini juga bikin IP login = IP kamu,
bukan IP datacenter VPS.)

Cara 1 (disarankan) — login lokal, copy folder accounts/ ke VPS:
  1. Di laptop (ada Chrome): siapkan accounts.json + proxy.txt, lalu
       node index.js login
     (login semua akun; tiap akun -> accounts/<label>/session.json; cookie ketangkep buat auto-perpanjang).
  2. Copy ke VPS. Kirim index.js + accounts.json + proxy.txt + config.json (sekali), DAN folder accounts/:
       rsync -av index.js accounts.json proxy.txt config.json accounts/ USER@VPS:~/TitanxBot-Sipal/
     - Yang WAJIB buat jalan: folder accounts/<label>/session.json. chrome-profile/ TIDAK perlu.
     - account.json OPSIONAL (cuma default bersama). Ga ada pun aman.
  3. Di VPS:
       cd ~/TitanxBot-Sipal && npm install          (butuh Node >= 22)
       pm2 start index.js --name titanxbot
       pm2 logs titanxbot                            (dashboard auto jadi log biasa di pm2)
       pm2 save && pm2 startup                       (biar auto-jalan habis reboot)
     CUKUP 1 proses pm2. Parent fork 3 worker sendiri — JANGAN start 3 pm2.

  Nyocokin otomatis: label di accounts.json = nama folder di accounts/. Bot baca
  accounts/<label>/session.json sesuai labelnya. Update rutin (habis re-login) = cukup copy
  ulang folder accounts/ (session-nya), lalu: pm2 restart titanxbot.

  (Opsional) Tanpa accounts.json di VPS pun bisa: bot bikin daftar akun dari NAMA FOLDER di accounts/,
  proxy diambil dari yang tersimpan di session (ke-stamp saat login). Tapi paling gampang & presisi:
  bawa sekalian accounts.json + proxy.txt (statis, copy sekali).

Cara 2 — login manual langsung di VPS (tanpa Chrome):
       node index.js login --manual --account pubiji
     -> print URL; buka di browser LAPTOP kamu, login, copy URL redirect (?code=...) balik ke VPS.
     Ulang tiap akun. KEKURANGAN: mode manual TIDAK nangkep cookie -> tidak bisa perpanjang otomatis,
     jadi tiap session habis (~7 hari) harus login manual lagi. Buat jangka panjang pakai Cara 1.

Catatan VPS:
  - Trafik API tiap akun tetap lewat proxy.txt (dari VPS pun). Aman.
  - pm2 restart/stop: worker otomatis berhenti + lepas lock; posisi/order yang ketinggalan
    dibereskan sendiri pas jalan lagi. Tidak ada lock nyangkut.
  - Session 7 hari diperpanjang sendiri (silent-auth, 12 jam sekali) selama bot jalan.

============================================================================
Umum (berlaku dua mode)
============================================================================

Alur otomatis per akun:
  session API (ed25519, 7 hari, diperpanjang sendiri)
  -> bind party Canton (sekali, 2captcha) -> bind referral (sekali, kode invite)
  -> faucet (kalau saldo < faucetBelowUsd, hormati cooldown server)
  -> volume engine (jalan terus):
     - 2-3 posisi sekaligus di market berbeda (BTC/SOL/ETH/CC, market yang ada posisi manual kamu dilewati)
     - entry/exit coba order MAKER dulu (fee 1.5 bps), digeser ikut harga, sisanya TAKER (4.5 bps)
     - ukuran = % margin bebas x leverage, dibatasi kedalaman orderbook; kadang angka bulat
     - hold, jeda, arah, leverage harian, sesi aktif, istirahat: semua acak
  -> points dicatat tiap 10 menit
  -> crash / paksa keluar? order & posisi bot yang tertinggal dibatalkan/ditutup saat jalan lagi
     (posisi manual kamu tidak pernah disentuh)

Volume vs saldo:
  Yang membatasi volume itu FEE, bukan kecepatan. Saldo ~10k habis kira-kira setelah $30-60 juta
  volume (tergantung porsi maker). Di bawah equityFloorUsd bot berhenti buka posisi baru dan nunggu
  faucet. Mau lebih awet: naikkan makerChance / makerWaitSec. Mau lebih cepat: turunkan.

Catatan login (dites 2026-10-09):
  Auth0 Titan TIDAK memberi refresh token. Bot memperpanjang login sendiri lewat cookie Auth0
  (silent auth) tiap 12 jam. Cookie mati kalau 3 hari tidak dipakai — selama bot jalan, tidak perlu
  login lagi. Kalau log bilang "perlu login" / "Jalankan: node index.js login", ulangi login akun itu.

File rahasia (account.json, accounts.json, proxy.txt, accounts/, session.json, chrome-profile/)
sudah di .gitignore — JANGAN dibagikan. Yang aman dibagikan: *.example.*, config.json, index.js.
